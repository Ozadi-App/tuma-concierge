# Security hardening rollout

This change closes the OTP disclosure, merchant digital-action permission gaps, phone-code attempt counter bypass and untrusted digital-file proxy requests identified on 31 October 2026. No database migration is required.

- OTP previews/logging are available only when `ENVIRONMENT=development` is explicitly set. Production, staging and an unset environment fail delivery when the provider is missing; password-reset requests retain a generic response. Configure working email/SMS delivery before relying on account recovery. Disabled/exhausted email pools continue to fail rather than expose codes.
- Digital files, licence management, refunds and course subroutes use merchant permissions. Refund/revoke actions follow `member_roles_refund_revoke`; other digital actions follow `member_roles_manage_digital`. Unknown merchant writes fall back to the store-management policy; cashier POS and draft-order creation remain available.
- Equivalent phone challenge encodings share the same five-attempt budget. The verify endpoint also has a source-address ceiling using the existing admin-controlled token-request limit.
- External file proxying is denied unless its exact hostname is in **Trusted download hosts** in the Admin digital option settings. The list starts empty. Approve only file providers whose operators and DNS you trust; merchant-controlled domains are not appropriate. IP literals, local hosts, non-HTTPS URLs, credentials and unusual ports are refused. Each redirect destination is checked again. Private R2 uploads continue to work. Existing external files need an approved provider or an upload to private storage; refusal happens before spending the buyer's download allowance. The existing direct external-link delivery option continues to work without a server-side fetch.
- Hono, the Node adapter, Zod and source-map-js are updated to patched versions. Zod 4 changes how omitted fields and defaults interact, so partial-update schemas explicitly preserve omission, enum maps stay partial, and nested object defaults are parsed with `prefault`. Publishing a course or updating one setting must not reset omitted prices or settings.

Validation includes the API typecheck, production dependency audit, targeted security regressions and the API suite. On this Windows workstation libsql's native dependency could not load; local database tests used an uncommitted Node SQLite adapter with the repository's D1 stand-ins and migrations. GitHub CI should run the normal native libsql suite on Linux before merge.

Fetch `origin`, merge current `origin/main` into the feature branch, resolve contributor changes and repeat relevant checks before merging through the PR. Deploy only from clean `main` matching `origin/main` using the repository's preflight script. This document does not claim that production provider settings or trusted-host configuration have been inspected or changed.
